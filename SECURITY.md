# Security Policy

## Supported Versions

At this time, security fixes are applied to the latest state of the default
branch.

## Reporting a Vulnerability

If you discover a security issue, please do not disclose it publicly first.

Report it by opening a private security advisory through GitHub:

1. Go to the repository's **Security** tab.
2. Select **Report a vulnerability**.
3. Provide reproduction details, impact, and suggested mitigations.

If private advisories are unavailable, open an issue with minimal details and
request a maintainer follow-up channel for sensitive information.

Please include:

- Affected component(s) and impact summary
- Clear reproduction steps or proof-of-concept
- Browser, OS, and version details
- Suggested remediation if available

## Preferred Disclosure Channel

- Primary: GitHub private security advisory (repository Security tab)
- Fallback: repository issue with minimal details and "security" label request

Do not post exploit details, payloads, or sensitive system data in public issues.

## Response Process

- We will acknowledge reports as soon as possible.
- We will assess impact and severity.
- We will prepare and validate a fix.
- We will coordinate responsible disclosure after remediation.

## Response Targets

- Initial acknowledgement: within 72 hours
- Triage and severity assessment: within 7 calendar days
- Remediation timeline: based on severity and exploitability
- Public disclosure: after a fix is available or risk is otherwise mitigated

## Dependency and Security Update Cadence

- Security dependency review cadence: monthly
- Out-of-band patching: immediate for critical/high-risk vulnerabilities
- Release communication: security-impacting fixes are summarized in `CHANGELOG.md`
